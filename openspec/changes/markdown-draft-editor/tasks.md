## 1. Schema and data access

- [ ] 1.1 Append exactly four nullable columns to the `posts` table in `db/schema.sql`: `draft_title text`, `draft_body_markdown text`, `draft_excerpt text`, and `draft_updated_at timestamptz`, each with an idempotent `ALTER TABLE posts ADD COLUMN IF NOT EXISTS` statement. Do not add a `draft_slug` column: per decision D1 a published post cannot change its public address, so a draft attached to a published post always has the row's stored `slug` (db/schema.sql:10), and a draft address column would have no value to hold that is different from it. The file today contains only CREATE TABLE and CREATE INDEX statements, measured. Assertion: the four columns exist and are nullable after the schema runs, and re-running the schema is a no-op. Verify: `npm run db:up && node --env-file-if-exists=.env scripts/reset-db.ts`.
- [ ] 1.2 Extend `app/lib/posts.server.ts` with draft-aware types and the four lifecycle functions `saveDraft`, `publishPost`, `discardDraft`, and a create-draft path, with the field-ownership rules from design Decision 2: a draft save on a draft-only row (`status = 'draft'`) writes `title`, `slug`, `body_markdown`, `excerpt`, and `updated_at`, and touches no publication time; a draft save on a published row writes only `draft_title`, `draft_body_markdown`, `draft_excerpt`, and `draft_updated_at`, and touches no published column and no publication time; a publish writes `title`, `body_markdown`, and `excerpt` from the draft values, sets `status = 'published'`, sets `published_at` only when it is currently null so a republish keeps the first publication time, sets `updated_at`, clears the four draft columns, and, for a published row, ignores any submitted slug and keeps the stored slug (D1); a discard draft sets the four draft columns and `draft_updated_at` to null and touches nothing else (D4). `updatePost` must not be reused for a draft save: it writes `slug`, `title`, `body_markdown`, `excerpt`, `status`, `published_at`, and `updated_at` on every call (app/lib/posts.server.ts:125-153), its SET list overwrites the published columns of a published row (:129-134), and its `published_at` CASE clears the publication time whenever the resulting status is `draft` (:135-139). Assertion: the new functions exist and typecheck passes with the field-ownership rules in place. Verify: `npm run typecheck`.

Assertion: the public queries never select a draft column. Verify: `npm run test`.

## 2. Validation

- [ ] 2.1 Split the validation in `app/lib/validation.ts` into a draft-save validation and a publish validation. A draft save requires a title and allows an empty body; a draft save with no title is rejected with a title error and no address error is shown. Publishing requires a non-empty body. The existing title (200), body (100,000), and excerpt (400) length limits apply to both. A submitted address is ignored for a published post: no address rule runs, and the post keeps its stored slug. A taken address on a draft save (new and draft-only posts) resolves to a numeric suffix through the existing all-row collision check (app/lib/posts.server.ts:44-56), and the save result carries a field message naming the resulting address. Assertion: each rule behaves as stated for both save kinds. Verify: `npm run test`.
