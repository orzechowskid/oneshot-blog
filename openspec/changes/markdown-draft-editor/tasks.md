- [x] 1.2 Extend `app/lib/posts.server.ts` with draft-aware types and the lifecycle functions for the intents of design Decision 2, with the exact field set per action. A draft save on a draft-only row (`status = 'draft'`) writes `title`, `slug`, `body_markdown`, `excerpt`, and `updated_at`, and touches no publication time; the `slug` goes through the existing all-row collision check with a numeric suffix (app/lib/posts.server.ts:44-56). A draft save on a published row writes only `draft_title`, `draft_body_markdown`, `draft_excerpt`, and `draft_updated_at`, and touches no published column and no publication time. A publish is split into two branches. Draft-only row: keep the existing content columns and the stored address, set `status = 'published'`, set `published_at` only when it is currently null so the first publication time is recorded, set `updated_at`, and clear the four draft columns. Published row: copy `title`, `body_markdown`, and `excerpt` from the draft columns, keep the stored address, set `status = 'published'`, set `published_at` only when it is currently null so a republish keeps the first publication time, set `updated_at`, and clear the four draft columns. The split is required, not optional: on a draft-only row the four draft columns are null while `title` and `body_markdown` are NOT NULL (db/schema.sql:11-12), so a single "copy from the draft columns" write fails with a not-null violation and the main publish path returns a server error. A discard draft sets the four draft columns and `draft_updated_at` to null and touches nothing else (D4). Address collisions end in a field error, never a server error: the collision check runs before the write, so two concurrent saves can both see a free candidate and one write then violates the UNIQUE constraint (db/schema.sql:10); a database unique violation on a draft save is caught, the draft is saved under the resulting suffixed address, and the result carries a field error on the address naming that address; the 50-attempt cap (app/lib/posts.server.ts:45) returns a field error, not a thrown Error. Remove `updatePost`: it wrote `slug`, `title`, `body_markdown`, `excerpt`, `status`, `published_at`, and `updated_at` on every call (app/lib/posts.server.ts:125-153), its SET list overwrote the published columns of a published row (:129-134), and its `published_at` CASE set `published_at` to null whenever the resulting status was `draft` (:135-139); the removal is part of the intentional removal of the unpublish path (D2). Its only caller is app/routes/admin-edit.tsx:109, so this task carries a paired deletion in that one file: remove the `updatePost` import specifier (app/routes/admin-edit.tsx:26) and the default-path block (app/routes/admin-edit.tsx:103-112), and replace the block with the no-intent response defined for task 5.3 — no write, and the editor is returned with an error naming the missing action — so typecheck passes before the new intents exist. Assertion: the new functions exist with the stated field sets, the two publish branches, the discard rule, and the collision field-error mapping; `updatePost` and its caller are gone; typecheck passes. Verify: `npm run typecheck`.
